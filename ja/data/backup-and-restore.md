# Marinaraのバックアップと復元

Marinara Engineのデータのコピーを保存し、後から戻す方法を説明します。アップデートの前、新しいデバイスへの移行前、[データを消去する](clearing-data.md)前に行ってください。

## 使う方法の選び方

| 方法 | 作られるもの | 用途 |
| --- | --- | --- |
| **Download Backup** | すべてのデータとファイルを収めた`.zip`。 | すべてをまるごと1つにしたコピー。 |
| **Export Profile** | アカウントのデータ(キャラクター、チャット、ロアブックなど)だけを収めた小さめのファイル。 | 秘密の値を含まないコピーや、他のツール向けのファイル。 |

`.zip`は、たくさんのファイルを1つにまとめたファイルです。どちらの方法も、復元も、**Settings → Data → Backup & Restore**(設定 → データ → バックアップと復元)にあります。

**始める前に:** Marinaraを動かしているコンピューターでは、これらの機能はそのまま使えます。スマートフォン、タブレットなどの別のデバイスから使う場合は、サーバーに管理者用のシークレットを設定し、同じ値を**Settings → Advanced → Security**に入力してください。管理者用のシークレットは、サーバーの`.env`ファイルに`ADMIN_SECRET`という設定で書くパスワードです。[サーバー設定リファレンス](../CONFIGURATION.md)の「Privileged APIs (ADMIN_SECRET)」のセクションと[リモートアクセス](../REMOTE_ACCESS.md)を参照してください。

## Download Backup

1. **Settings → Data**(設定 → データ)を開きます。
2. **Backup & Restore**(バックアップと復元)で**Download Backup**をクリックします。ボタンの表示は**Creating backup…**になります。
3. ブラウザーが確認したらファイルを保存します。または、ダウンロードフォルダーで見つけます。

`.zip`には次のものが入っています。

- 保存済みのテキストデータ(キャラクター、チャット、ロアブック、プリセット、接続、設定)
- アップロードしたファイルと生成したファイル(アバター、スプライト、背景、ギャラリーの画像、フォント、カスタム絵文字とスタンプ、自分で設定した通知音など)
- `.encryption-key`ファイル(存在する場合)
- 手作業での復元方法を書いた`RESTORE.txt`のメモ([手作業での復元](#restore-by-hand)を参照)

フォルダー名については、[Marinaraがデータを保存する場所](where-data-is-stored.md)を参照してください。

> **Warning:** バックアップには、保存済みのAPIキーと、それを復号する`.encryption-key`ファイルが入っています。絶対に共有しないでください。他人に見られない場所に保管してください。

Androidではアプリのデータフォルダーに手が届きません。そのため、デバイスの外にコピーを取り出すには**Download Backup**を使います。

うまくいかなかった場合: 「Backup preparation timed out after one hour.」と表示されたら、もう一度試してください。別のデバイスからダウンロードできない場合は、管理者用のシークレットを確認してください(上記を参照)。

<a id="automatic-backups"></a>

## 自動バックアップ

Marinaraは、動かしているコンピューター上で、スケジュールに沿って完全バックアップを作れます。

1. **Settings → Data → Backup & Restore**を開きます。
2. **Automatic backups**をオンにします。
3. **Daily**、**Weekly**、**Monthly**のいずれかを選びます。
4. **Automatic backups kept**を1から9999までの範囲で設定します。

Marinaraは、オンにしてまもなく最初のバックアップを作ります。実行のたびに、新しいバックアップを設定した数まで残し、古い自動バックアップを削除します。**Download Backup**で作ったバックアップは削除しません。

自動バックアップは、データフォルダー内の`backups/`フォルダーにあります。最新のものは`marinara-automatic-backup.zip`です。古いものは、名前に日付と時刻が付きます。形式は**Download Backup**と同じです。

新しいアーカイブが完成するまで古いものが残るため、実行のたびに完全なアーカイブ1つ分の空き容量が必要です。空き容量が足りないと、Marinaraはその回をスキップし、設定の横に理由を表示します。空き容量ができたら、再試行します。

> **Tip:** データフォルダーの外にも、コピーをもう1つ置いてください。ディスクの故障やアプリの消去では、自動バックアップも一緒に消えます。

## プロファイルのエクスポート

1. **Settings → Data → Backup & Restore**を開きます。
2. **Export Profile**をクリックします。同じタイトルのウィンドウが開きます。
3. 形式を選びます。
4. ブラウザーがファイルをダウンロードします。

- **Marinara Native**は、キャラクター、ペルソナ、チャット、ロアブック、プリセット、エージェント、テーマ、Personal Extensionのコード、メディアを保持します。APIキー、Webhookのリンク、一部のチャット設定は復元されません([キーの再入力](#enter-your-keys-again)を参照)。Marinaraで復元できます。
- **Compatible JSON**は、他のツール向けに、素のキャラクター、ペルソナ、ロアブックのファイルを集めた`.zip`を作ります。Marinaraでは復元できません。

ネイティブ形式のプロファイルは、`marinara-profile.json`としてダウンロードされます。大きすぎる場合、MarinaraはZIPファイルを代わりに提案します。**Export ZIP**をクリックすると、`marinara-profile.zip`がダウンロードされます。

ネイティブ形式のプロファイルは、正規表現スクリプト、そのフォルダー、各フォルダーの一時停止設定を保持します。個別のスクリプトをJSONとして共有するには、[正規表現スクリプト](../extending/regex-scripts.md#import-and-replace-scripts)を参照してください。

ネイティブ形式のプロファイルにはPersonal Extensionのコードも残りますが、有効かどうかの状態と承認は残りません。復元された拡張機能はすべて無効の状態で入ります。**Library → Extensions**で、もう一度確認してください。

## Import Profileでの復元

**Import Profile**は、プロファイルのファイルまたは**Download Backup**の`.zip`を読み込みます。

1. **Settings → Data → Backup & Restore**を開きます。
2. ボタンの下の**Tag imported**(インポート済みをタグ付け)と**Tag source**(出典をタグ付け)にチェックを入れたままにすると、取り込むキャラクター、ペルソナ、ロアブック、プリセット、チャットに**Imported**(インポート済み)と**Backup**(バックアップ)のタグが付きます。すべてを元の状態のまま復元するには、チェックを外します。
3. **Import Profile (JSON/ZIP)**をクリックします。
4. `marinara-profile.json`、`marinara-profile.zip`、またはバックアップの`.zip`を選びます。ボタンの表示は**Scanning Profile...**になります。
5. **Import Profile**ウィンドウを読みます。Marinaraが見つけた内容が一覧表示されます。[不足分だけを追加する](#only-add-whats-missing)場合を除き、Marinaraにすでにある項目は、ファイル内のバージョンに置き換わります。
6. 続けるなら**Import**を、やめるなら**Cancel**をクリックします。ボタンの表示は**Importing Profile...**になります。Marinaraはまず、復元に備えてデータのコピーを保存し、その後に進捗バーが表示されます。完了すると、プロファイルをインポートしたというメッセージが表示されます。

うまくいかなかった場合:

- `localhost`、`127.0.0.1`、`[::1]`以外でMarinaraを開いている場合、プロファイルのインポートにはHTTPSが必要です。エラーは「Profile import requires HTTPS outside local development.」です。HTTPSのアドレスでMarinaraを開いてください。
- `.zip`の中にメディアのファイルが一部欠けていても、インポートは最後まで進みます。欠けているものを列挙した警告が表示され、Marinaraは残りをインポートします。
- 復元用コピーを保存するためのディスクの空き容量が足りない場合は、何もインポートされません。エラーメッセージは「Nothing was imported, because a safety copy could not be saved first.」で始まります。完全なバックアップと同じくらいの空き容量を確保してから、もう一度インポートしてください。

同じプロファイルを2回インポートすると、Marinaraは項目をコピーせずに更新します。かなり古いバージョンのプロファイルでは、重複が作られることがあります。

### 不足分だけを追加する

削除後に行った変更を失わずに、削除したものを取り戻すには、**Import Profile (JSON/ZIP)**の上にある**Keep my current versions, only add what's missing**(現在のバージョンを保持し、不足分だけを追加)をオンにしてから、上記の手順でインポートしてください。Marinaraにすでにある項目とファイルはすべてそのまま残り、Marinaraにないものだけが追加されます。戻したかった項目だけでなく、個別のメッセージやロアブックのエントリーなど、ファイルを保存してから削除したものすべてが対象です。長期記憶は1つの項目として扱われます。Marinaraにすでに長期記憶がある場合、ファイル内の長期記憶は追加されません。

何も置き換わらないため、Marinaraは復元用コピーを保存しません。**Undo Last Import**(前回のインポートを取り消す)は、引き続き今回より前のインポートを取り消します。

かなり古いバージョンのプロファイルでは、この方法は使えません。常に既存の項目とは別に項目が追加され、**Import Profile**ウィンドウにもそのように表示されます。

### インポートの取り消し

項目を置き換えるインポートの前には毎回、Marinaraがデータの完全なコピーをデータフォルダー内の`backups/`フォルダーに保存します。ファイル名は`marinara-before-import-`で始まり、その後に日時が続きます。インポートが完了すると、前のインポート時のコピーは削除され、最新の1つだけが保持されます。

1. **Settings → Data → Backup & Restore**(設定 → データ → バックアップと復元)を開きます。
2. **Undo Last Import**(前回のインポートを取り消す)をクリックします。その下の行に、復元用コピーの保存日時が表示されます。
3. 確認ウィンドウで**Undo Last Import**をクリックして確定します。

取り消すと、前回のインポートで置き換えられた項目とファイルが、元のバージョンに戻ります。インポート後にそれらの項目を変更していた場合、その変更は失われます。インポートで追加された項目を含め、それ以外はすべてそのまま残ります。インポートの取り消しは1回だけでき、その後、復元用コピーは削除されます。

取り消しても、安全のためにインポートでオフになったものはオンに戻りません。次のものは手動でオンにし直してください。

- 使用中だったテーマ
- Personal Extensions(**Settings → Addons**(設定 → アドオン)でもう一度確認してください)
- スクリプトやWebhookを実行するカスタムツール
- Professor Mariの記憶

インポートで接続のAPIキーが消去された場合は、キーを入力し直してください([キーの再入力](#enter-your-keys-again)を参照)。その接続をデフォルトやフォールバックに使っていた場合は、もう一度そのように設定してください。

インポートで置き換えられた分岐チャットは、分岐元のチャットとのリンクが外れたままです。そのリンクはインポートですでに削除されており、取り消しでは復元できません。

かなり古いバージョンのプロファイルは項目を追加するだけなので、Marinaraは復元用コピーを保存せず、取り消せるものはありません。

復元用コピーは、完全なバックアップと同じ容量を使います。インポートを取り消さずにその容量を空けるには、**Settings → Data → Backup & Restore**で**Delete Safety Copy**(復元用コピーを削除)をクリックし、確認してください。データはそのままですが、そのインポートを取り消すことはできなくなります。インポートが中断された場合、**Delete Safety Copy**だけが表示されることがあります。その場合、コピーを取り消しに使うことはできませんが、削除はできます。

<a id="enter-your-keys-again"></a>

## キーの再入力

**Import Profile**は、**Download Backup**の`.zip`からでも、APIキーとWebhookのリンクを復元しません。APIキーとは、サービスが発行する秘密のコードです。プロファイルのファイルと、バックアップの中のプロファイルでは、これらの値が空になっています。そのため、新しいコンピューターにインポートした後は、次の手順で入力し直します。

1. **Library → Connections**(ライブラリー → 接続)を開きます。
2. 使っているアカウントを1つずつ開き、APIキーを入力して保存します。[AIプロバイダーへの接続](../connections/connecting-to-a-provider.md)を参照してください。
3. Webhookのリンクを使うカスタムツールごとに、リンクを入力し直します。

アドレスやキーを含む一部のチャット設定(Discord、DeepL、Intiface)も、空の状態で戻ります。各チャットの**Chat Settings**で入力し直してください。

インポートで、同じインストールにすでに設定したキーが空になることはありません。

## 新しいコンピューターへの移行

1. 新しいコンピューターにMarinaraをインストールして起動します。[インストール](../INSTALLATION.md)を参照してください。
2. **Settings → Data → Backup & Restore**を開き、**Import Profile (JSON/ZIP)**をクリックします。
3. **Download Backup**の`.zip`またはプロファイルのファイルを選び、**Import**をクリックします。
4. 上で説明したとおり、APIキーを入力し直します。

バックアップに入っているキーのファイルが役に立つのは、次のようにデータフォルダー全体を手作業でコピーする場合だけです。

<a id="restore-by-hand"></a>

## 手作業での復元

**Import Profile**が使えない場合にだけ使ってください。`.zip`の中には、たとえば`marinara-backup-...`のようなフォルダーが1つあり、`RESTORE.txt`のメモが入っています。

1. Marinaraを停止します。
2. バックアップを展開します。
3. 展開したフォルダーから、各フォルダーと`.encryption-key`ファイルを、データフォルダーへコピーします。[Marinaraがデータを保存する場所](where-data-is-stored.md)を参照してください。
4. Marinaraを起動します。

`.encryption-key`ファイルは`storage`フォルダーと一緒に置いてください。そうしないと、保存済みのAPIキーを読み取れません。

**Backup & Restore**(バックアップと復元)の**Existing backups**一覧は、通常は空です。この一覧は使う必要がありません。
